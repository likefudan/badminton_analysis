# 每次击球的技术类型（badminton strokes）

`badminton strokes` 给每次击球写出谁打的、是什么技术，以及有多大把握。单打和双打都能用，是后面用关节数据判断「动作是否到位」的基础。

这是第一期，还没有人工标注，所以没有准确率数字。在业余手机录像上，大约一半到三分之二的击球被标成「没把握」。用法是先把它当作预标注，人工核对之后再拿来分析。

## 怎么跑

前提：已经有逐帧骨架、球轨迹和击球时刻。

```bash
badminton skeleton 视频.mp4 --court 视频.court.json --stride 1
```

```bash
badminton shuttle 视频.mp4 --court 视频.court.json
```

```bash
badminton hits 视频.mp4 --court 视频.court.json
```

```bash
badminton strokes 视频.mp4 --court 视频.court.json --hits 视频.hits.json
```

不给 `--hits` 时，会当场按 `badminton hits` 的办法找击球。需要 PyTorch，以及 BST 的不合并类别权重 `bst_CG_AP_JnB_bone.pt`。权重默认放在 `~/codebase/third_party/BST_weights/weight/`，下载办法见 [bst_trial.md](bst_trial.md)。作者还发布了同一设置的其他随机种子（`_2`、`_3`），用 `--weights` 一起给就会取平均。

输出：

| 文件 | 内容 |
| --- | --- |
| `视频.strokes.json` | 每拍的帧号、击球人、类型、所属大类、概率、第二和第三可能的类型、直线/对角、平高/高远的依据数值、是否需要人工看。所有值的来源都是 `derived`（推算） |
| `视频.strokes.csv` | 同样的内容，一拍一行 |
| `视频.strokes.mp4` | 在击球人头顶写出类型，停留 1 秒。没把握的用灰字，并加问号 |

## 类型怎么来

主类型由 [BST](bst_trial.md) 给出。这次换成了作者不合并类别的权重：35 类，等于 ShuttleSet 的 17 种类型分远端和近端，再加一个「未知」。ShuttleSet 的类型名改成了常用叫法，并分成大类：

| 大类 | 类型（ShuttleSet 原名） |
| --- | --- |
| 杀球 | 杀球（殺球）、点杀（點扣） |
| 吊球 | 吊球（切球）、过渡吊球（過渡切球） |
| 放网 | 放网（放小球） |
| 勾对角 | 勾对角（勾球） |
| 推扑 | 推球（推球）、扑球（撲球） |
| 挑球 | 挑球（挑球）、防守挑球（防守回挑） |
| 高远/平高 | 高远球、平高球（都是長球，靠下面的规则分开） |
| 抽挡 | 平抽（平球）、后场抽平（後場抽平球）、防守抽球（防守回抽）、挡网（擋小球） |
| 发球 | 发短球、发长球 |

和 PR #12 的试跑相比，改了这几处：

- **击球人已知，只在击球人那一侧的类别里选。** 击球时刻识别已经给出了击球人，所以不再让模型自己判断远端还是近端。
- **送进模型的两个人从球员跟踪里取：击球人，加上对面接下一拍的人。** 如果这是回合的最后一拍，就取对面在这段时间里出现最多的人。BST 的结构写死了两个人，双打也照这样只送两个人，不需要重新训练。以前按「每边第一个检测到的人」取，在手机录像里经常取到场边的人。
- **球员短暂丢失（不超过 0.1 秒）时，用前后两帧插值补上。**
- **球员在底线后约 2 米以内时不再丢掉这一帧，站位截到场地边上。** BST 自己的规则是球员一出界，这一帧就全部填 0。业余球员常在底线后击球，jay_vs_cdl 里有一半的帧因此被清空。

附加属性不是 BST 给的，而是根据下一拍击球人站在哪里推算出来的：

- **直线/对角**：比较击球人和下一拍击球人的横向位置。差 2 米以上算对角，1.2 米以内算直线，介于两者之间的不判断。发球不判断，回合的最后一拍也不判断。
- **平高/高远**：只对长球判断。用两人之间的距离除以两次击球的间隔，得到球的平均地面速度，8 米/秒以上算平高。

这两条规则的阈值是估计值，要用标注数据校准。

## 第一期没做的

劈杀、劈吊、收吊、搓球（展搓）这几类，ShuttleSet 没有标注。它们和普通杀、吊、放网的区别在拍面和手腕：骨架里没有球拍，手机画面上也看不清。所以要等有了人工标注，再在 BST 上加一个分类头来学。每类要有 50 拍以上才值得做。

单打录像用的是 `outputs/hits/` 里的骨架、球和击球时刻。IMG_0971 是双打，逐帧重跑了骨架和击球时刻。

| 录像 | 击球数 | 概率中位数 | 判成未知 | 没把握 |
| --- | --- | --- | --- | --- |

## 双打类型模型（DShuttleNet 训练，2026-11-15）

结论：用 DShuttleNet 的职业双打标注训练了一个 9 类模型。在 5 场转播双打上按场次留出，我们自己识别出的击球里它判对 **79%**，同一批击球上 BST 是 **67%**。在手机录像 IMG_0971 的 18 拍人工标注上是 7 拍对 6 拍，看不出更好，所以**默认不开**，用 `--doubles-model auto` 打开。

### 数据和类别

DShuttleNet（CC BY-NC-SA 4.0，只能非商业使用）有 58 场 BWF 双打、5.8 万拍，每拍标了 9 类之一：发短球、发长球、放网、推球、挑球、平抽、杀球、吊球、高远球，以及四个人的站位。其中 5 场下了视频并跑过骨架、球轨迹和击球识别（见 [hits.md](hits.md)「DShuttleNet 双打对照」）。劈杀、劈吊、收吊、搓球它也没有标。

### 模型看什么

- **站位和节奏**（51 个数）：击球时四个人的站位（击球人、搭档、对面靠网的、对面靠后的；场地转成击球人总在近端），下一拍和上一拍离这一拍多久、谁打的、那时四个人站在哪，以及这是不是回合的第一拍。这些标注里本来就有，所以这一部分用没有视频的 53 场（4.6 万拍）训练，训练时随机去掉 20% 的拍、站位加 0.3 米噪声，模拟漏检和追踪误差。上一拍或下一拍如果是击球人自己这一边打的，说明中间漏了对面的一拍，就当作不知道。
- **姿态和球**（击球前 0.33 秒到击球后 0.63 秒，每秒 30 次）：击球人的 17 个关节、球相对击球人和相对场地在画面里的位置、四个人的站位。这部分要用我们自己的骨架和球轨迹，所以只能在有视频的 5 场上学（小 Transformer，2 层，宽 128）。

9 类定下来之后，BST 只在这一类对应的 ShuttleSet 类型里细分（杀球还是点杀、挑球还是防守挑球、放网还是挡网还是勾对角……），输出格式不变，每拍多一个 `model` 字段（`dshuttlenet` 或 `bst`）。击球人没有追踪位置的拍仍然全由 BST 判断。

### 转播双打上的结果

5 场轮流留出 1 场做测试，其余 4 场训练；站位和节奏部分始终不看这 5 场。「识别出的击球」是 `badminton hits` 找到、并且在标注 ±3 帧内的拍（4592 拍），击球人也用它给的；「标注的击球」用标注帧号和标注站位对应的追踪（5456 拍，找不到击球人追踪的算错）。BST 的 17 类按含义并成 9 类再比（挡网算放网，扑球算推球）。

| 比赛 | 项目 | 识别出的击球：新模型 | 只用站位和节奏 | BST | 标注的击球：新模型 | BST |
| --- | --- | --- | --- | --- | --- | --- |
| BAEK_LEE_KIM_KONG All England 2024 | 女双 | 81.7% | 74.1% | 64.4% | 82.8% | 63.6% |
| Baek_Lee_Fukushima_Hirota Indonesia Open 2023 | 女双 | 80.3% | 84.3% | 74.7% | 80.0% | 76.0% |
| CHIA_SOH_LEE_YANG All England 2024 | 男双 | 78.3% | 66.8% | 60.5% | 74.0% | 55.8% |
| LIANG_WANG_CHIA_SOH China Open 2023 | 男双 | 69.9% | 59.8% | 61.0% | 72.3% | 59.7% |
| ZHENG_HUANG_JIANG_WEI World Tour Finals 2024 | 混双 | 74.6% | 66.0% | 63.2% | 73.6% | 61.6% |
| 合计 | | **78.9%** | 74.5% | 67.0% | 78.7% | 66.1% |

- 各类平均的 F1：新模型 0.78，BST 0.64。击球人也判对的那部分拍里，新模型 80.9%。
- 错得最多的是放网和平抽互相混（约 100 拍各一个方向）、推球被判成放网或平抽（推球只对了不到一半）、挑球判成平抽。发短球、杀球、挑球、高远球都在 85% 以上。
- 站位和节奏部分如果用标注里的站位，留出的 5 场能到 85%；换成我们追踪出来的站位掉到 78%。差的这几个点主要在男双：追踪丢人、串号多。球员追踪改好之后这里会跟着涨。
- 训练用 MPS，每次结果有 ±1 个点的随机波动。

### 手机录像上

IMG_0971（手机双打，侧面机位，60 帧/秒，骨架每 2 帧一次）有 18 拍人工标了类型。击球帧和击球人都用人工标的：

| | 9 类对上 | 细类也对上 |
| --- | --- | --- |
| BST | 6/18 | 4/18 |
| 新模型（BST 细分） | 7/18 | 5/18 |

18 拍太少，分不出高下。看逐拍的输入，问题在三处：这段的标注只覆盖识别出来的击球，中间漏掉的拍让「下一拍是谁、隔多久」经常是错的；侧面机位下站位和姿态的投影都和转播不同；业余球速慢，同样的类型节奏不一样。新模型错的时候把握还很高（常在 0.8 以上），不像 BST 那样会标「没把握」，所以拿它做预标注反而容易漏看。等手机录像有 100 拍以上的类型标注，再决定要不要默认打开，也可以拿这些标注接着微调。

### 怎么跑

```bash
python scripts/train_stroke_classifier.py features <eval 目录>/*/*.rallies.mp4 -o cache/ --bst
```

```bash
python scripts/train_stroke_classifier.py train <DShuttleNet raw 目录> --cache cache/ -o ~/.cache/badminton/stroke_classifier_dshuttlenet.pt
```

```bash
badminton strokes 视频.mp4 --court 视频.court.json --doubles-model auto
```

`features` 读 `scripts/dshuttlenet_hits.py` 和流水线留在每个回合片段旁边的文件；`train` 先打印按场次留出的分数，给了 `-o` 再用 5 场一起训练并保存。权重不放进仓库（数据是非商业许可）。
