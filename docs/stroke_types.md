# 每次击球的技术类型（badminton strokes）

`badminton strokes` 给每次击球写出谁打的、是什么技术，以及有多大把握。单打和双打都能用，是后面用关节数据判断「动作是否到位」的基础。

这是第一期，还没有人工标注，所以没有准确率数字。在业余手机录像上，大约一半到三分之二的击球被标成「没把握」。用法是先把它当作预标注，人工核对之后再拿来分析。

## 怎么跑

前提：已经有逐帧骨架、球轨迹和击球时刻。

```bash
badminton skeleton 视频.mp4 --court 视频.court.json --stride 1
```

```bash
badminton shuttle 视频.mp4 --court 视频.court.json
```

```bash
badminton hits 视频.mp4 --court 视频.court.json
```

```bash
badminton strokes 视频.mp4 --court 视频.court.json --hits 视频.hits.json
```

不给 `--hits` 时，会当场按 `badminton hits` 的办法找击球。需要 PyTorch，以及 BST 的不合并类别权重 `bst_CG_AP_JnB_bone.pt`。权重默认放在 `~/codebase/third_party/BST_weights/weight/`，下载办法见 [bst_trial.md](bst_trial.md)。作者还发布了同一设置的其他随机种子（`_2`、`_3`），用 `--weights` 一起给就会取平均。

输出：

| 文件 | 内容 |
| --- | --- |
| `视频.strokes.json` | 每拍的帧号、击球人、类型、所属大类、概率、第二和第三可能的类型、直线/对角、平高/高远的依据数值、是否需要人工看。所有值的来源都是 `derived`（推算） |
| `视频.strokes.csv` | 同样的内容，一拍一行 |
| `视频.strokes.mp4` | 在击球人头顶写出类型，停留 1 秒。没把握的用灰字，并加问号 |

## 类型怎么来

主类型由 [BST](bst_trial.md) 给出。这次换成了作者不合并类别的权重：35 类，等于 ShuttleSet 的 17 种类型分远端和近端，再加一个「未知」。ShuttleSet 的类型名改成了常用叫法，并分成大类：

| 大类 | 类型（ShuttleSet 原名） |
| --- | --- |
| 杀球 | 杀球（殺球）、点杀（點扣） |
| 吊球 | 吊球（切球）、过渡吊球（過渡切球） |
| 放网 | 放网（放小球） |
| 勾对角 | 勾对角（勾球） |
| 推扑 | 推球（推球）、扑球（撲球） |
| 挑球 | 挑球（挑球）、防守挑球（防守回挑） |
| 高远/平高 | 高远球、平高球（都是長球，靠下面的规则分开） |
| 抽挡 | 平抽（平球）、后场抽平（後場抽平球）、防守抽球（防守回抽）、挡网（擋小球） |
| 发球 | 发短球、发长球 |

和 PR #12 的试跑相比，改了这几处：

- **击球人已知，只在击球人那一侧的类别里选。** 击球时刻识别已经给出了击球人，所以不再让模型自己判断远端还是近端。
- **送进模型的两个人从球员跟踪里取：击球人，加上对面接下一拍的人。** 如果这是回合的最后一拍，就取对面在这段时间里出现最多的人。BST 的结构写死了两个人，双打也照这样只送两个人，不需要重新训练。以前按「每边第一个检测到的人」取，在手机录像里经常取到场边的人。
- **球员短暂丢失（不超过 0.1 秒）时，用前后两帧插值补上。**
- **球员在底线后约 2 米以内时不再丢掉这一帧，站位截到场地边上。** BST 自己的规则是球员一出界，这一帧就全部填 0。业余球员常在底线后击球，jay_vs_cdl 里有一半的帧因此被清空。

附加属性不是 BST 给的，而是根据下一拍击球人站在哪里推算出来的：

- **直线/对角**：比较击球人和下一拍击球人的横向位置。差 2 米以上算对角，1.2 米以内算直线，介于两者之间的不判断。发球不判断，回合的最后一拍也不判断。
- **平高/高远**：只对长球判断。用两人之间的距离除以两次击球的间隔，得到球的平均地面速度，8 米/秒以上算平高。

这两条规则的阈值是估计值，要用标注数据校准。

## 第一期没做的

劈杀、劈吊、收吊、搓球（展搓）这几类，ShuttleSet 没有标注。它们和普通杀、吊、放网的区别在拍面和手腕：骨架里没有球拍，手机画面上也看不清。所以要等有了人工标注，再在 BST 上加一个分类头来学。每类要有 50 拍以上才值得做。

## 在现有录像上跑的结果

单打录像用的是 `outputs/hits/` 里的骨架、球和击球时刻。IMG_0971 是双打，逐帧重跑了骨架和击球时刻。

| 录像 | 击球数 | 概率中位数 | 判成未知 | 没把握 |
| --- | --- | --- | --- | --- |
| singles.mp4（转播单打） | 61 | 0.81 | 1 | 12 |
| IMG_8923（手机单打） | 110 | 0.45 | 19 | 76 |
| jay_vs_cdl（手机单打） | 100 | 0.55 | 26 | 60 |
| IMG_0971（手机双打，侧面机位） | 24 | 0.50 | 6 | 16 |

和 PR #12 的试跑方式相比，jay_vs_cdl 判成未知的从 36 拍降到 26 拍，主要是因为不再丢掉底线后面的帧。

IMG_0971 的机位在场地侧面，而 BST 是用底线后方高处的转播画面训练的。机位不同，关节的投影方式就不同，所以这段的结果参考价值最低。建议新录像都从底线后方的高处拍。

## 下一步

1. 用网页标注工具标击球类型：每拍有一个类型字段，外加劈、收、搓、直线、对角几个标记，并用这里的输出预填。先标 100 拍，就能有准确率数字，同时用来校准直线/对角和平高的阈值。
2. 标到 300 到 400 拍之后，用 ShuttleSet 加上自己的标注一起微调 BST，并加上劈、收、搓的分类。
