# 击球动作指标（技术分析第 1 阶段）

`badminton technique` 在 `badminton strokes` 的结果上，按击球类型给每一拍量几样动作数字。
调研和完整计划见 [调研文档](https://claude.ai/artifact/DPaeCc5cycxLWNfgVQkzJx)。

```bash
badminton strokes  VIDEO.mp4 --court VIDEO.court.json --no-video   # 先有击球类型
badminton technique VIDEO.mp4 --court VIDEO.court.json              # 写 VIDEO.technique.json / .csv
```

## 量什么

窗口是击球前 0.8 秒到击球后 0.4 秒。长度都以躯干长（两肩中点到两髋中点）为单位，所以远近、高矮的人能比。
角度是画面里看到的角度，不是真实关节角，只适合同一机位之间比较。

| 类型 | 指标 | 意思 |
| --- | --- | --- |
| 杀球、高远/平高、吊球 | `contact_height` | 击球时手腕高出两肩多少 |
| | `elbow_deg` | 击球时肩-肘-腕夹角 |
| | `backswing_elbow` | 引拍时持拍肘最高抬到肩上多少 |
| | `chain_ms`、`chain_order_ok` | 髋、肩、肘、腕各自最快的时刻（相对击球，毫秒），是否从髋到腕依次 |
| | `wrist_speed` | 手腕最快速度（躯干长/秒） |
| | `turn` | 肩线左右宽度变化的幅度，转体的代理量 |
| | `jump` | 击球前脚踝升高多少 |
| | `follow_through` | 击球后手腕沿击球前的横向方向继续扫过多远 |
| | `disguise`（只有吊球） | 吊球的引拍和自己杀球的引拍差多少，除以杀球之间本身的差别；1 左右说明看不出来 |
| 放网、勾对角、挑球、推扑、抽挡 | `contact_height`、`wrist_speed` | 同上 |
| | `stance` | 击球时两脚间距 |
| | `knee_deg` | 弯曲那条腿的膝角 |
| | `trunk_lean` | 躯干偏离竖直的角度 |

默认只分析近端球员（`--sides near`），远端人太小；默认跳过类型没把握的击球（`--include-review` 也算上）。
关节在窗口里有 30% 以上时间看不清的拍不出数字，`reason` 写原因。姿态模型侧身、背身时常把左右标反，所以持拍臂不看左右标签：在击球附近两只手腕都看得见的一帧，有球的位置时取明显离球更近的手腕；没有时高手位取更高的手腕、其它球取击球前后动得更多的手腕（弓步时空手往后伸，「离肩更远」会选错），再按前后帧连续性一帧帧跟出手腕、肘、肩。高手位的击球时刻取击球前后 0.15 秒内持拍手腕的最高点（`contact_shift_ms` 是相对检测到的击球时刻挪了多少；0.25 秒内找不到最高点时不挪，`contact_unclear` 为真，这时击球点、肘角、随挥不给数）。最高点时持拍手还在肩下的高手位球多半是类型判错，不出数。发力顺序只看击球前 0.5 秒到击球后 0.05 秒，手腕的峰值只在击球前 0.15 秒内找；整段挥拍里手腕最快的时刻远早于击球（`wrist_peak_early`，多半是引拍落拍或姿态点抖）时不判顺序；四个关节同时到峰值也不算「对」。球的位置离两只手腕都超过 1.2 个躯干长（比如球在网那边）时不用「离球近」这条。

## 参考分布和提示

仓库自带职业近端参考 `src/badminton/technique_ref_pro_near.json`：FineBadminton 14 场 1080p 单打转播，用标注的击球时刻和类型（`scripts/finebadminton_strokes.py` 转成 strokes.json），只取近端球员，约 1,800 拍。`badminton technique` 默认就和它比（`--reference none` 关掉，或给自己的 JSON）。
远端球员的击球点低 0.3–0.4 个躯干长、起跳是假的（往后退时脚在画面里往上走），所以用户的近端录像只和近端参考比。

每个数字都写百分位（`percentiles`）；只有比较可信的几项落在 10% 以下或 90% 以上时写进 `notes`：击球点、两脚间距、膝角、躯干前倾、吊球伪装。
转体（和机位高度有关，转播机位比手机高）、起跳（前后移动被当成起跳）、肘角（职业杀球 p10 只有 42–78°，多是姿态错）和发力顺序（职业高手位也只有 31% 判为「对」）照样算、写进 JSON，但不写提示。
手腕速度、随挥、引拍肘高也不写提示：转播从后方高处拍，向前挥拍大多是纵深方向、画面里显得小；手机在侧面拍时同样的动作在画面里是横向的，会被系统性地判成「偏高」。等有和转播机位一致的录像再打开。

自己合参考：`badminton technique-ref ref.json A.technique.json B.technique.json ...`（每种球、每个指标的 10/25/50/75/90 百分位）。

`summary` 里每种球、每个人有均值和标准差；`steadiness` 是「同一个人拍与拍之间的波动 ÷ 所有人的波动」（至少两个人各有 3 拍才算，只有一个人时这个比值恒为 1），
越小说明这个指标越能区分人、越值得信。第 1 阶段的门槛就是看这几个指标在真实录像上稳不稳。
