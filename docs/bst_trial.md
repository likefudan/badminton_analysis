# 击球类型识别：BST 试跑

结论：BST 发布的 ShuttleSet 权重可以直接吃我们现有的骨架、球轨迹和球场标定，在 `data/singles.mp4`（转播单打，72 秒）上跑通了，找到 64 次击球并给出类型。抽查的几段（跳杀接挡网、后场高远球）和画面对得上。没有人工标注，所以准确率还没法给数字。

BST 是什么：[Badminton Stroke-type Transformer](https://github.com/Va6lue/BST-Badminton-Stroke-type-Transformer)（CVPR 2026 workshop，MIT 许可）。输入是击球前后一小段时间里两名球员的 2D 关节、两人在球场上的位置、球的轨迹，输出这一拍的类型。不看画面本身，所以很小（185 万参数），64 段在 CPU 上 0.2 秒算完。

## 怎么跑

BST 的代码和权重不在本仓库里。代码不需要（网络结构在 `src/badminton/bst.py` 里重写了一份，和原版逐位一致），只需要权重。权重在作者的 [Google Drive 文件夹](https://drive.google.com/drive/folders/1D4172WZDJWPvpJdpaHDhy_cA-s8F-zR5)里，要的是 `bst_CG_AP_JnB_bone_merged.pt`、`..._merged_2.pt`、`..._merged_3.pt`（25 类、每段 30 帧的 BST-CG-AP，三个是同一设置不同随机种子训练的）。文件夹里有 459 个文件，整包下载会被 Google 限流，单个下就行。下面假设放在 `~/codebase/third_party/BST_weights/weight/`。

```bash
badminton skeleton data/singles.mp4 --court data/singles.court.json --singles --stride 1 -o outputs/bst/singles.skeleton.mp4
```

```bash
badminton shuttle data/singles.mp4 --court data/singles.court.json -o outputs/bst/singles.shuttle.csv
```

```bash
python scripts/bst_trial.py --skeleton outputs/bst/singles.skeleton.npz --shuttle outputs/bst/singles.shuttle.csv --court data/singles.court.json --weights ~/codebase/third_party/BST_weights/weight/bst_CG_AP_JnB_bone_merged*.pt --video outputs/bst/singles.skeleton.mp4 -o outputs/bst/singles
```

注意骨架要加 `--stride 1`：默认每 2 帧跑一次，而 BST 每段要 1 秒里的 30 帧。需要 PyTorch（用的是 2.15，没有兼容旧版的代码）。

输出：

| 文件 | 内容 |
| --- | --- |
| `singles.strokes.csv` | 每次击球一行：帧号、时间、谁打的（`far` 远端 / `near` 近端）、类型、概率、第二第三可能的类型 |
| `singles.strokes.mp4` | 骨架视频上，在击球的人头顶写出类型和概率，停留 1 秒 |
| `singles.inputs.npz` | 送进网络的数组和输出的概率，方便核对 |

## 我们的数据怎么转成 BST 的输入

BST 的 README 强调输入必须和它训练时的归一化方式一样。下面每一项都是照它的 `prepare_train_on_shuttleset.py` 做的（`bst.build_sequence`、`bst.model_inputs`）。

| BST 要的 | 它训练时怎么来的 | 我们怎么给 |
| --- | --- | --- |
| 关节 `(30, 2, 17, 2)` | MMPose（RTMDet + RTMPose-m）的 17 个 COCO 关节，减去人框中心，除以人框对角线 | `skeleton.npz` 的 `keypoints` 和 `bbox`（YOLOX-m + RTMPose-m），同样的算法 |
| 骨骼 `(30, 2, 19, 2)` | 19 对关节相减，和关节拼成 36 个点、72 个数 | 一样 |
| 站位 `(30, 2, 2)` | 两个脚踝用单应矩阵变到球场上再取中点，按双打外框归一化到 0 到 1（横向从画面左到右，纵向从远端底线到近端底线） | 两个脚踝用 `court.json` 变到球场（米），`x / 6.10`，`1 - y / 13.40` |
| 球 `(30, 2)` | TrackNetV3 的像素坐标除以视频宽高，看不见是 `(0, 0)` | `badminton shuttle` 的 CSV，一样 |
| 球员顺序 | 远端（画面上方）在前，近端在后 | `side == 1` 在前，`side == 0` 在后 |
| 坏帧 | 场内不是正好两个人的帧，关节、站位、球全部填 0 | 一样（任一方没检测到，或脚的位置出了球场外框 1% 以上） |
| 切段 | 击球帧前后各半秒，共 30 帧（30fps） | 一样；60fps 的视频取 60 帧再隔帧抽成 30 帧，用的是它自己的 `make_seq_len_same` |

核对过的两件事：

1. ShuttleSet 的球场边界是单打线还是双打线，README 没说。用它 `homography.csv` 里的矩阵把四个角点变到球场上，宽长比是 0.4545，等于 6.10 / 13.40，所以是双打外框。
2. 重写的网络和原版对比：三个权重文件（30 帧 25 类、100 帧 25 类、30 帧 35 类）都能严格加载，随机输入下输出的最大差是 0。

和训练数据仍然不一样的地方：

- 人框来自 YOLOX 而不是 RTMDet，框的松紧会略有不同，而关节是按框归一化的。
- `singles.mp4` 里有 6.3% 的帧被当成坏帧填了 0，基本都是球员退到底线后面的时候。这是 BST 自己的规则，它训练时也这样，所以照做了。
- 业余手机视频机位低、球轨迹差，和转播差得更远，这次没有试。

## 击球时刻：先用的简单切段

正式的击球时刻识别在另一个线程做。这里先用一个粗的办法（`bst.find_hits`）：球的速度在相邻两小段之间突变（按 1080p、30fps 折算超过 12 像素/帧），而且这一刻有球员的手腕离球不到 1 个人框高度；同一个人连续两次只留变化更大的那次。

`scripts/bst_trial.py --hits 文件.csv` 可以换成别的击球时刻，只要 CSV 里有一列 `frame`。

击球帧差几帧对结果的影响（同一批 64 次击球，整体挪动后类型不变的比例）：

| 偏移 | 类型不变 |
| --- | --- |
| 早 3 帧 | 83% |
| 晚 3 帧 | 75% |
| 早 6 帧 | 52% |
| 晚 6 帧 | 66% |

所以击球时刻识别的误差最好在 3 帧（0.1 秒）以内。

## 结果怎么看

- 64 次击球里，最高概率的中位数是 0.62；23 次在 0.8 以上，20 次低于 0.5，4 次判成「未知」。
- 模型判断的击球方（类别自带远端 / 近端）和简单切段按手腕距离判断的击球方，60 次里 55 次一致。这两个是独立得出的，可以互相校验。
- 三个种子各自的结果和三者平均的结果有 84% 相同，说明有一部分击球模型自己也拿不准。
- 连起来看是合理的：杀球后面跟挡网前球，挑球后面跟高远球或杀球，发球出现在回合开头。
- 作者报告的测试集准确率是 82.5%（25 类，top-2 95%）。我们的数据上会低一些，低多少要有人工标注才知道。

12 种类型（远端、近端各一套，加一个「未知」共 25 类）：放网前球、挡网前球、杀球、挑球、高远球、平抽球、吊球、推球、扑球、勾对角、发短球、发长球。

## 双打怎么办

BST 只支持两个人，这是写死在结构里的：前面的时间卷积和时间 Transformer 对每个人共用同一套权重，和球做交叉注意力也是每人各做一次；但最后把「远端球员、近端球员、球」三路拼起来分类，类别本身也是「远端 × 12 种 + 近端 × 12 种」。训练数据 ShuttleSet 也全是单打。

三条路，按投入从小到大：

1. 不重新训练，每次击球只挑两个人送进去：击球的人，加上对面离球最近（或下一拍接球）的人，按远端 / 近端的顺序排好。输入形状完全不变，现在的代码改一下选人就能跑。击球的人由击球时刻识别给出，所以还可以只在这个人那一侧的 12 个类别里选。风险是双打和单打差别大：站位（前后站）、球路（平抽和推扑多，高远球少）、发球都不一样，模型没见过。这条路成本最低，建议先试，前提是双打视频上击球时刻和四个人的跟踪已经可靠。
2. 只看击球者的模型：输入改成击球者一个人的关节和站位加上球，输出 12 类，不分远近端。这样单打双打通用。可以用 ShuttleSet 训练，作者在 Google Drive 上放了预处理好的 `.npy` 数据，不用下比赛视频；作者的代码里也有只用单人姿态的数据集类。需要改结构并训练，网络小，M5 上应该能训。少了对手的信息准确率会掉一些，掉多少要训了才知道。
3. 真正的四人模型，用双打数据训练或微调：结构上把最后的融合改成对四个人做注意力即可，但需要带击球类型标注的双打数据。我没有找到公开的、规模够用的双打击球类型数据集，这意味着要自己标，量至少几千拍。

建议的顺序是先 1 后 2。1 能很快告诉我们单打模型在双打上差多少；如果差得多，2 是不需要自己标数据的办法。3 留到有标注工具和标注量之后。

另外，无论哪条路，业余手机视频（机位低、60fps、球轨迹不稳）本身就是比「双打」更大的一道坎，应该先在一段业余单打上试一次。

## 这次没做的

- 没有人工标注，没有准确率数字。标 50 到 100 拍就能有个大致的数。
- 没有接进 `badminton` 命令行和 `pyproject.toml`（另外几个线程在改这些文件）。等击球时刻识别合进来后再接，接口上只需要击球帧号。
- 没有试每段 100 帧的权重（两次击球之间的整段，作者报告准确率略高，83.2%），因为它的切段依赖前后两次击球的时刻。`bst.load_model(权重, seq_len=100)` 已经能加载。
- `cut.py` 的 `render_label` 用同样的方式找中文字体，在这台机器上会选到 PingFang.ttc 的第一个字体（香港繁体），缺「杀」「远」等简体字。它现在写的字正好都有，所以没出问题；试跑脚本里按字体名选对了。
